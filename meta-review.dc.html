meta-review

Adversarial, multi-lens review: prioritized findings, blind-spot probes, and one reusable lesson.

// what it does

A friendly review finds what's easy to find. meta-review is adversarial — it reviews the work through several hostile lenses at once (correctness, clarity, security, the case you didn't consider) and reports findings ranked by impact, not by the order it noticed them.

It probes for blind spots on purpose, and every pass leaves one reusable lesson — so the same class of mistake gets caught earlier next time.

// the lenses
prioritized findings

P1/P2/P3 by real impact — you fix the worst thing first.

blind-spot probes

Deliberate questions aimed where you weren't looking.

a reusable lesson

One takeaway to fold into your craft so it won't recur.

// invoke it
/meta-review <the work you want stress-tested>

Returns prioritized findings, blind-spot probes, and one reusable lesson. It argues with the work so you don't ship the version that only you could love.

Grounding

The ideas here aren't invented — the skill generalizes established practice into one reusable, task-agnostic move. Below: the prior art it builds on, and the in-repo contract it actually runs on.

Prior art
Red-teaming — adversarial review from security and model evaluation: attack the work to find what a friendly read misses.
Six Thinking Hats — Edward de Bono (1985) — switch perspectives deliberately so one lens's conclusion doesn't suppress another's.
Severity triage (P1 / P2 / P3) — defect-tracking practice — fix what blocks ship before what merely polishes.
In this suite
The lens catalog references/lens-catalog.md — always Adversarial + Clarity, plus the domain lenses — the blind-spot probes, and the correctness > safety > scope > coherence > clarity fix order.
