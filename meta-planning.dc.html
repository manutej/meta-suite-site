meta-planning

A typed plan scaffold — the structure a fleet of agents executes, written before the plan itself is.

// what it does

A normal plan is a to-do list — prose an agent has to interpret. A meta-plan is a typed structure: tasks with declared inputs, outputs, and dependencies, so they can be handed to parallel agents without a human re-explaining each one.

You describe the goal in a line. It emits the shape the work takes — what runs in parallel, what must wait, and how the pieces merge back into one shipped result.

// the anatomy
tasks

Each a typed unit — declared inputs, a single output, an owner.

dependencies

What must finish first. Everything else runs in parallel by default.

merge

The rule that folds the parallel outputs back into one deliverable.

// invoke it
/meta-planning <a goal big enough to split>

Returns a typed plan: parallelizable tasks, their dependency edges, and a merge rule — ready to hand to a fleet of agents or work solo, top to bottom.

Grounding

The ideas here aren't invented — the skill generalizes established practice into one reusable, task-agnostic move. Below: the prior art it builds on, and the in-repo contract it actually runs on.

Prior art
Work-unit graphs & critical path — decompose a task into typed units under a partial order; parallelize only the lanes that are genuinely independent. DAG · CPM
Kaizen — Masaaki Imai (1986) — the small-batch continuous-improvement loop the plan's KAIZEN stage encodes.
Stop-the-line (Andon) — Toyota Production System — any work unit can halt the run the moment a gate fails.
